What is a shader?

A shader is a tiny program the GPU runs for every vertex or every pixel. It's written in GLSL, which looks a lot like C, so if you know C++ or C# you can already read it.

The key idea: you don't write a loop over the screen. You write what one pixel does, and the GPU runs that code for all of them at the same time. Each copy only answers one question: where does this point go? or what color is this pixel?

Why the GPU?

2.07Mpixels in one 1920 × 1080 frame
× 60frames every second
≈ 124Mcolor decisions per second, at minimum

A CPU has a few fast cores that work through tasks in order. A GPU has thousands of simple cores that all run the same shader on different pixels at once. Think a few expert chefs versus a stadium of line cooks following one recipe card.

Same shape, different shader

Both pictures below use the exact same math for the shape: the distance from each pixel to a line. The only difference is what the shader does with that distance. By the end of this lesson you'll understand every line of the one on the right.

The graphics pipeline

        
Every frame in a game takes the same path from triangles to pixels. Two stops are yours to program; the GPU handles the rest.

        
    
          
  1. VerticesYour mesh: a list of corner positions, plus colors or texture coordinates.
    2. 
          
  2. Vertex shaderRuns once per corner and moves it to where it lands on screen.
    3. 
          
  3. RasterizerJoins corners into triangles and finds every pixel each one covers.
    4. 
          
  4. Fragment shaderRuns once per covered pixel and picks that pixel's color.
    5. 
          
  5. FramebufferColors are depth-tested, blended and shown on screen.
    6.

Vertex shader: where does this point go?

        


#version 330 core
layout (location = 0) in vec3 aPos;
uniform mat4 uMVP;

void main() {
    gl_Position = uMVP * vec4(aPos, 1.0);
}

          

            
in
Data for this one vertex, from your mesh.

            
uniform
The same for every vertex: camera, time, transforms. uMVP moves the object into the world, in front of the camera, and flattens 3D onto the screen.

            
gl_Position
The answer: where this corner lands.

          

        


        
Fragment shader: what color is this pixel?

        


#version 330 core
out vec4 FragColor;
uniform float uTime;

void main() {
    float pulse = 0.5 + 0.5 * sin(uTime);
    FragColor = vec4(0.0, 0.52 * pulse, 0.79, 1.0);
}

          

            
Every pixel at once
One run per pixel the triangle covers.

            
No peeking
A pixel can't see what its neighbors decided.

            
One output
An RGBA color, each channel 0.0 to 1.0.

          

        


        
So what is Shadertoy doing?

        
It draws one triangle big enough to cover the whole screen, so every pixel gets a fragment, and then runs your mainImage() as the fragment shader. All the work happens in the fragment stage, which is why Shadertoy art can look 3D with no meshes at all. You can do the same in your own C++ OpenGL window: draw one full-screen triangle and load the same fragment shader.


        
Activity 2: Shapes from equations

        
To draw a shape with math, describe it by its distance. For a circle with center c and radius r, at pixel p:

        
float d = length(p - c) - r;   // a signed distance

        
    
          
  • d < 0: the pixel is inside the circle.
    • 
          
  • d = 0: it's exactly on the edge.
    • 
          
  • d > 0: it's outside, and d says how far.
    • 
        

        
Every shape in this lesson starts as one of these numbers, then gets colored by its sign.

Level up: one trick, big difference

        
The gap between a bland shader and a memorable one is usually a single idea. Here are two more. Open either in the playground and flip BLAND between 0 and 1.


        
Fake 3D: a circle becomes a planet

        
No mesh and no 3D engine. For each pixel inside the circle, the Pythagorean theorem gives the height of a sphere at that point, which gives a surface direction (the normal). Compare that direction with a light direction and you get shading.

        
vec3 n = normalize(vec3(p, sqrt(r*r - dot(p, p))));  // the circle bulged into a sphere
col = base * max(dot(n, light), 0.0);                // facing the light = bright

        


        
Perspective and repetition: a gradient becomes a synthwave sunset

        
Dividing by the distance to the horizon is how perspective works: things farther away get squeezed together. fract() makes anything repeat forever, so one line becomes an infinite grid, and adding iTime makes you fly over it.

        
float z = 1.0 / (horizon - p.y);                                // farther = bigger z
float grid = smoothstep(0.44, 0.5, abs(fract(p.x * z) - 0.5));  // fract() repeats forever

From stick to saber
